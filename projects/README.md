# Participant Project Showcase

> Looking for the finished projects? Visit the **[2026 Summer Project Wall](../SHOWCASE.md)** for the complete visual gallery, including the TOP 3 Creators, source repositories, demos, and technical profiles.

This directory collects **one Markdown file per participant project** submitted via **Pull Request**. Engineers review these files before merge.

---

## Filename Rule (Mandatory)

```
<ParticipantName>-Project-<ProjectSlug>.md
```

**Good:** `Jamie-Project-WarehousePatrol.md`  
**Bad:** `project.md`, `Jamie 项目.md`, `final_FINAL.md`

- **ParticipantName:** how you want to be credited (ASCII recommended).  
- **ProjectSlug:** short English identifier (PascalCase or hyphenated).

---

## Required Content (Checklist)

Your Markdown **must** include all of the following sections:

| Section | Description |
|---------|-------------|
| **Project name** | Public title. |
| **Participant name** | Same as in filename (can add team members). |
| **Project summary** | 120–300 words: problem, approach, stage completed. |
| **GitHub repo link** | Public URL to **your** source repository. |
| **Demo video link** | YouTube or equivalent (Stage 1 may use shorter clip if allowed that season). |
| **Technical highlights** | Bullets: models, sensors, BPU usage, ROS 2 graph summary, metrics (FPS/latency). |

---

## Optional but Encouraged

- Architecture diagram (image link).  
- **Community post** permalink.  
- **Benchmark table** (resolution, model, FPS, CPU/BPU load).  
- **License** name for your code repo.
